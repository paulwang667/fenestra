# 触摸滚动的惯性和边界回弹 设计

## 为什么做

在手机上（一加 6），fenestra 的滚动是"手指拖多少就滚多少，抬手立刻停"，到头时也没有任何反馈。这是 wechat-ui 和原生应用手感差距最大的地方：长列表要一下一下地拖，用户也分不清是滚到底了还是卡住了。用户要求按流程自行实施这项改进（2026-10-27）。

## 目标

1. **惯性（fling）**：手指快速划过后抬起，内容继续滑行并逐渐减速停下。
2. **接住**：滑行中手指按下，滑行立刻停下，这次按下不算点击。
3. **边界回弹**：拖过头时内容跟着手指走但越来越"沉"（橡皮筋）；松手后弹回边缘。滑行撞到边缘时冲出一小段再弹回。
4. Android 和 iOS 都有，行为一致。

## 不做什么

- **桌面不变。** 鼠标滚轮、触控板的滚动行为、截图基准都不变；触控板的惯性由 macOS 自己提供。新行为只来自触摸手势（`touch.rs` 的 `GESTURES` 平台）。
- **嵌套滚动的接力**（内层到头后把剩余滑动交给外层）：不做，保持现在"落点所在的那个滚动容器"的规则。
- **Android 12 的拉伸效果、旧版的边缘光晕**：不做，两个平台都用同一种橡皮筋回弹（我的决定，见文末）。
- **多指手势、双指缩放**：不做。

## 反目标（做了也算失败的情况）

- 改变了桌面或无头渲染的任何像素，或任何现有测试的行为。
- 滑行中轻点一下，结果触发了按钮、打开了会话。
- 聊天消息流"贴底"的行为被破坏：回弹之后不再跟随新消息。
- 回弹时滚动条、`scroll_offset()` 读到负数或超过最大值的偏移（应用和测试依赖它在范围内）。
- 滑行或回弹结束后还在一直请求重绘（耗电）。

## 怎么做（已定的部分）

### 分工

- **shell（`touch.rs`）**：只管手指。拖动时发出新的 `InputEvent::Pan { dx, dy }`（取代现在触摸拖动时发的 `Wheel`）；抬手时根据最近的移动算出速度，发出 `InputEvent::PanEnd { vx, vy }`（逻辑像素每秒，没有速度时为 0）。手指按下时，如果**落点所在的滚动容器**正在惯性或回弹中（问 core：`FrameState` 提供带落点的查询，用上一帧做命中），这次触摸进入"接住"状态：发 `InputEvent::PanStop`，不发 `PointerDown`，不触发长按；抬手时不点击，只发 `PanEnd`（有速度就再滑，没有就让越界的部分弹回）；之后若拖过点击阈值，照常拖动。落点不在正在动的容器里（比如滑行中点返回、点底部标签），按下照常是点击。
- **core**：滚动的物理都在 core。`Pan` 和 `Wheel` 一样先给 `on_wheel` 元素优先处理（保持画布平移等现有行为；被它吃掉的手势也不滑行），否则按落点找各轴最近的滚动容器。`PanEnd` 把速度交给那个容器开始惯性（已经越界时速度交给回弹的弹簧）；`PanStop` 只停下落点所在容器（各轴）的惯性和回弹：越界量**停在当时的位置**，手指按着时不动；接着拖动时从当前越界量继续算橡皮筋（把显示量反解成原始拖动量，和 iOS 一样）；随后的 `PanEnd` 再让它弹回。每次建帧时推进物理（按时间的解析式），运动中把 `animating` 置真以保持出帧。

### 状态

- 每个滚动条目新增：速度（每轴）、越界量 `stretch`（每轴，视觉上的越界位移）、上次推进的时间、上次已知的最大偏移。
- **逻辑偏移始终在 `0..=max` 内**：`scroll_offset()`、滚动条位置、贴底判断都只看它。越界量只用于绘制（子元素原点额外平移）和命中测试（与绘制一致）。

### 参数（我的决定，便于实现时直接用）

- **速度估计**：取抬手前 100ms 内的移动样本，用首尾位移除以时间；如果抬手前最后一次移动早于 50ms，速度为 0（手指停住了再抬）。速度上限 8000 逻辑像素每秒。
- **起滑门槛**：速度低于 50 逻辑像素每秒不滑行。
- **减速**：指数衰减 v(t) = v0·e^(−t/τ)，τ = 0.325 秒（接近 iOS 和 Android 的默认手感，滑行距离约 v0·τ）。速度低于 20 逻辑像素每秒时停下。
- **拖动时的橡皮筋**：越界的原始拖动量 x 映射为显示量 (1 − 1/(x·0.55/d + 1))·d，d 为该轴视口尺寸（iOS 的公式）。
- **回弹**：越界后用临界阻尼弹簧拉回边缘，约 0.4 秒内稳定（ω ≈ 12/秒）。滑行撞边时，把撞边那一刻的速度交给弹簧，冲出一段再回来；冲出量不超过视口的 1/4。
- **减少动态效果**（`reduced_motion`）：保留惯性（这是直接操作，不是装饰），去掉橡皮筋和回弹：拖过头和撞边都硬停在边缘。注意：手机上 shell 目前不读系统的"减弱动态效果"设置（永远是关），所以这条在真机上暂时不会触发，只在无头测试和以后接上系统设置时生效；接系统设置不在本次范围。
- **冲出量上限**：撞边时把交给弹簧的速度截断，使冲出量不超过视口的 1/4。
- **贴底**：回弹不改逻辑偏移，所以贴底判断不受影响；滑行停在底部时恢复贴底。

### 兼容性

- `InputEvent` 新增三个变体。它不是 `#[non_exhaustive]`，外部对它的穷尽匹配会编译失败，要在 CHANGELOG 里写明。
- 无头 `Harness` 不经过 `touch.rs`；测试直接注入 `Pan` / `PanEnd` / `PanStop`，用 `pump` 推进时钟。

## 怎么验证

- core：滑行距离与参数一致、逐渐减速并停下且不再请求重绘；撞边回弹后回到边缘；拖过头时位移按橡皮筋公式；`PanStop` 立刻停下；`reduced_motion` 下没有越界；贴底的消息流回弹后仍贴底；滚轮行为不变。
- shell：速度估计（快速划、停住再抬、样本太少）；接住时不点击；拖动发的是 `Pan`。
- 真机（一加 6）：会话列表、聊天消息流、通讯录上划动、接住、拖过头、撞边，录屏或截图；滑行时帧间隔仍约 16.7ms。

## 留给实现者

- 物理推进放在 `FrameState` 的哪个函数、`Scroll` 结构怎么扩展。
- 速度样本的存法（小环形缓冲即可）。
- `PanStop` 时怎么让 shell 知道"有滚动在动"：`FrameState` 提供一个查询即可。

## 我替用户做的决定

- 两个平台都用 iOS 式橡皮筋，而不是 Android 12 的拉伸或光晕：一种实现、两边一致，且 wechat-ui 风格选项里本来就有苹果风格。
- 参数取 iOS 默认手感附近的值。
- 减少动态效果时保留惯性、去掉回弹。
- 不做嵌套滚动接力。
